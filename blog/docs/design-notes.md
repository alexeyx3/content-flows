# Design notes: why the blog flow works the way it does

The rules themselves live in `AGENTS.md`, `.agents/skills/blog-article/SKILL.md`, the role files
under `agents-src/agents/` and the cards in `knowledge/`. This file records the reason behind each
rule, so that someone adapting the flow knows what a rule protects before changing it. Record
shared decisions here whenever you change the flow.

## Structure of the flow

| Rule | Why |
|---|---|
| The parent session orchestrates and starts every specialist directly as a flat depth-1 agent. There is no intermediate coordinator; the `blog-coordinator` profile is kept dormant. | A local Codex runtime may give a depth-1 agent no delegation tools, so a coordinator in the middle could not start its own specialists. Nested `codex exec` launches are forbidden for the same reason. |
| The parent runs scripts and gates but does not research, draft, edit or fact-check prose. | An agent that produced a text cannot give an independent verdict on it, and prose written by the orchestrator bypasses every role contract. |
| Every specialist starts with `fork_turns="none"` and a fixed routing envelope: job path, metrics stage ID, role file, and for the writer the requested H2 or for rework the exact defect and its diff path. The parent adds no editorial guidance, length judgement or suggested conclusion. | The role file and the job artifacts are the complete instruction. Anything the parent adds is its own reading of the content task and differs from run to run. |
| Prompts name files; they do not embed file contents. State passes only through the job folder. | Pasted artifacts inflate the parent context on every turn and drift from the files that the gates actually validate. |
| A job owns only its folder under `jobs/`. Research artifacts and verified evidence may be reused from an adjacent job; prose never. | Articles in one queue share a vendor base, and copied passages travel from article to article almost verbatim. |
| Writes to shared files are locked: the `companies` lock before any stage that may enrich vendor cards, the `site-urls` lock around a site-map refresh. A parallel batch may set `company_enrichment_mode: read_only`. | Evidence agents of several jobs running at once would write the same card files. Read-only mode keeps verified enrichment candidates in job-local evidence for a later owner; it does not relax sourcing or entailment. |
| New rules are switched on by version flags in `job.yaml` (`workflow_version`, `research_v3_version`, `visual_qa_version`, `source_policy_version`, `answer_contract_version` and others). Existing jobs are not migrated; a validator for an absent flag is a no-op. | A rule change must not silently invalidate work that was accepted, sealed or published under the earlier contract. |
| Each job keeps `progress.md`: request, decisions, stage, files and checks, open issues, review links, explicit approvals. | A later session resumes from the folder alone and can tell an actual human approval from a machine PASS. |
| Keeping the topic sheet current and creating the review document after QA have standing permission. CMS media, drafts and publication need an explicit request in the current conversation. | The first two are reversible bookkeeping. A CMS write changes what readers see, and the flow must never infer it. |
| The limit on concurrent agent threads is raised in `.codex/config.toml`. | With a low limit the four research lanes of several jobs queued behind each other and batch time grew for no content reason. |
| Tests are collected from `tests/` only (`pytest.ini`), and commands name the tested Python runtime. | Test discovery once picked up the tests of a vendored third-party package and failed before any project test ran; a newer default interpreter lacked the pipeline libraries. |

## Topic selection and duplicate checks

| Rule | Why |
|---|---|
| Topics come only from the sheet in `config/temnik.json`, strictly top to bottom. A later row is not taken while an earlier unprocessed row has not been evaluated. | An early selection drew topics from a different shared spreadsheet and picked the attractive ones. A fixed source and order remove cherry-picking. |
| Every skipped or duplicate row gets a specific reason in the sheet (`temnik.py skip`), and a duplicate gets the URL of the page that covers it. | The next selection must not re-evaluate the same rows, and the publisher can see why a row was passed over. |
| Candidate rows are proposed and approved by the publisher before any SERP, research or brief is spent on them. | Research was once started on the first unprocessed row before the publisher had chosen; the work had to be stopped. |
| `temnik.py preflight` searches published CMS articles and local jobs by title, slug, summary and H2s with full-text search and adds local embedding similarity. The scores are retrieval signals; the reviewer reads the nearest pages and records a reader-intent rationale with `topic_overlap.py decide`. | Overlapping roundups were discovered only after publication. Lexical search misses a page with the same intent in different words, and a similarity score cannot decide whether two intents are the same. |
| The overlap search is repeated after the brief has resolved the real primary query (`--stage resolved`). The brief validator fails until that decision matches the brief, and the CMS export rejects a missing decision or a newly indexed strong match. | The seed row is a clue; the query the article finally targets can collide with a page the seed did not, and the catalogue changes between selection and publication. |
| `temnik.py start --apply` refuses a job without a current reviewed report and re-checks that the live and local catalogue has not changed. | A report reviewed against yesterday's catalogue does not cover a page published since. |
| Country-specific hiring topics belong to the country guides and pure definitions to the glossary. Shared definitions or subtopics do not make an independent article a duplicate. | Each flow owns one format with its own CMS contract; standalone articles legitimately repeat mandatory background. |
| `Topic` and `Top keyword` are research clues copied from another page. A number such as "Top 10", a year or a competitor's phrasing is not inherited; the primary query is resolved from recurring wording in live SERP titles, descriptions and H1s, and the H1 is original. | The seed describes someone else's page. A list size taken from it forces padding or cutting, and a copied title competes with its source instead of answering the query better. |
| The slug never contains a year; `strapi_publish.py` refuses one. The year may appear in the H1 and `metaTitle` of Best and Top articles. | A batch once went out with a year in the address and had to be renamed minutes after publication. A year in the URL forces a redirect every January, while a year in the title is updated with the text. |
| For a head-to-head format the SERP decides whether a buyer query exists; the run stops at the SERP when it does not, with the reason recorded in the job folder. | A pair of vendor names can show demand for reasons that have nothing to do with choosing between them. |
| A format the publisher has paused is deferred with an explicit reason and stays in the queue; it is not marked skip or duplicate. | A pause is temporary and says nothing about the topic. |
| The row is updated at four boundaries: start, packaged, review document, verified live publication. `temnik.py publish` writes `published` only when the public URL returns HTTP 200 and the CMS record has `publishedAt` and a cover. | A locally finished or review-only article must never look published in the tracker. |

## SERP in several markets and the synthesis

| Rule | Why |
|---|---|
| Every English topic is captured in four English-language markets: US, GB, DE and AU. The builder's `--require-geo` guards stop the run unless each market has organic rows. | One market hides useful subtopics, and the largest result set otherwise gets treated as universal without anyone deciding so. |
| Two providers with one output contract: XMLRiver first, DataForSEO as fallback. A provider error returns a non-zero exit, and `--resume` re-requests only the failed query–market pairs. | An outage once produced a header-only file that looked like a successful capture. Providers also fail for single markets during a batch, and a full rerun repeats paid requests. |
| Repeated URLs are fetched once and keep every market and position in which they ranked. A URL present in several markets is one source with several labels. | Otherwise the same page is counted as several independent confirmations of a subtopic. |
| The script extracts H1–H4 of the ranking pages. The brief agent does not browse those pages again to reconstruct headings; it browses only for independent research and current facts. | A model browsing pass over pages the script already parsed costs a full stage and adds nothing. |
| `serp.hybrid_outline.md` is the coverage-maximal, de-duplicated union of every useful intent, question, entity, distinction and example across the markets. Only true duplicates, irrelevant material, navigation and promotional boilerplate are removed. There is no cap on H2, H3, H4, vendors or FAQ questions. | De-duplication is not shortening. An outline trimmed to a tidy table of contents answers the query less completely than the pages it competes with. |
| The four markets define discovery only. They are not a list of countries for research, examples, FAQ or visuals. | An early article toured the same four countries in section after section because they were the sampled markets. A country is mentioned when it changes a reader decision, and a national rule keeps its national scope. |
| Reddit is one bounded discovery packet: two search requests through the SERP provider, indexed titles and snippets, no crawling. Failure or an empty packet does not block the job. | It supplies reader language, objections and hidden criteria the SERP misses. A snippet is never evidence, and a theme counts as recurring only when independent threads express it. |
| SERP analysis stays invisible in the article: no search query as the subject of a sentence, no talk of roundups, competitor articles or what this article will do. | The reader is solving a task, not running a query. Drafts repeatedly echoed the content strategy into the prose and the publisher struck it out. |

## Research map and parallel research packets

| Rule | Why |
|---|---|
| After SERP and Reddit, `blog-research-map` writes a compact map of reader decisions with stable `Q-xx` IDs, including the affected parties. The four research specialists start only after it validates. | A search planned from headings once missed a study that answered a reader decision directly. Naming decisions first gives every lane the same target and makes a gap visible. |
| Each search-log row names the decisions it covers (`decision_refs`), and the validator checks that every decision is covered. A material gap is closed inside the same research stage. | A separate research rerun after the article costs a second pass, and its findings arrive after the brief was approved. Coverage of the log lowers the risk of an omission; it does not prove that every existing source was found. |
| Four lanes run in parallel as separate depth-1 threads with separate outputs and validators: topic (`research.md`, `research.discovery.md`), primary documents (`research.data.json`), studies (`research.studies.json`), outside quotes (`research.quotes.json`). The brief waits for all of them. | When one researcher owned everything, the file-type search was described in the role but not carried out in full, and outside voices were searched too narrowly. Separate packets make each search checkable; parallel lanes keep wall time down. |
| The primary-document lane runs real `filetype:` queries for four format families (PDF, slides, word documents, spreadsheets) and at least one `site:` or `inurl:` query through `fetch_google_serp.py`, and archives the results in `raw/document-search-*.csv`. The validator compares the query log with the archive and requires at least one original that was actually read. | A note saying "searched, nothing found" cannot be verified. An archive proves the search happened, and a read original proves it reached a source. |
| `read_original` is a research status, not permission to publish. Evidence reopens every selected original and verifies each claim and each plotted point. | The agent that found a number is not independent of it. |
| There is no quota of statistics, charts, studies or quotes. An empty result is valid with a real search log and a specific reason (`no_data_reason`, `no_transferable_study_reason`). | A quota produces a decorative study or an invented data point. An honest "none" is better than either; an empty packet without a credible search is not accepted. |
| A catalogue record, abstract, DOI, snippet or AI summary is a lead. A study counts only after the original is read, with its method, population, outcome, year and the risk of transferring it to this audience. Sample size is kept separate from the outcome. | Metadata cannot support an effect claim. A narrow sample gets generalized to the world, and a sample size gets quoted as if it were a finding. |
| Outside quotes are searched in X, indexed LinkedIn pages, ordinary web search and practitioners' own publications. Snippets and reposts are leads; LinkedIn is not scraped. A candidate becomes `verified_original` only after the original is opened and the exact words, author, role, date and context are checked. An excerpt is at most 25 words. | Early articles carried only staff comments because nothing else was looked for. A quotation lifted from a snippet risks wrong words or a wrong author under a real person's name. |
| The topic researcher produces a GIST packet: a decision map, a search log and insight cards, each mapped to a reader action. | Information gain has to change a choice, a verification, an avoidance or a calculation. A new citation that restates context adds nothing to the SERP. |
| If direct figures are absent, the document researcher may broaden to an adjacent outcome that serves the same decision and must mark the transfer limit. | One failed query is not an exhausted search, and an adjacent finding presented as a direct one misleads. |

## Brief, sections contract and the publisher checkpoint

| Rule | Why |
|---|---|
| Information gain is mandatory: at least one item the top results do not say, backed by an independent source they do not cite. Without it the brief reports `blocked`. | The article must be more useful than each page it competes with, and an invented "extra" is worse than none. |
| No length target exists anywhere. `validate_article_brief.py` rejects a word count or length in `sections.json`; competitor word counts are research diagnostics; the word count is measured after drafting for analytics only. | A writer who knows a target pads up to it or compresses under it. A measurement on published articles showed that length did not track results: the shortest of a set outperformed the longest. |
| `sections.json` is an ordered list of sections with unique kebab-case IDs and the approved H2–H4 hierarchy. Detailed per-section micro-briefs, minimum-point checklists and prose recipes are not written. | The hierarchy plus the research context is the plan. Detailed section instructions were echoed back into the prose and turned sections into checklists. |
| The outline in `brief.md` and `sections.json` match one-to-one. The primary query is also a machine-readable table row, and the four final meta values are written in one exact line format. | Packaging and the overlap gate read these fields deterministically; a value that exists only in prose was repeatedly missed by the parser. |
| Answer contract (`answer_checks`): each load-bearing reader question is linked to the qualified facts that answer it and then to the actual answer in the finished text, including captions and tables. No new agent and no sentence-by-sentence extraction is added. | A sampled audit of finished articles found an FAQ that explained a neighbouring concept instead of giving the promised answer, and a visual caption that broadened a condition the body text had kept. |
| Delivery contract (opt-in `batch_delivery_contract_version`): the concrete obligations the brief selected (tables, internal navigation, wording, source qualifiers) get stable IDs and are audited by the native QA reviewer. | Audits found omitted tables, links and qualifications in drafts that had passed QA. An API critic cannot certify this audit for itself. |
| Geographic audit: the brief states the intended scope, the reasoning for the jurisdictions chosen and the risk of a source imbalance. The editor and QA compare that frame with the weight of the final text. | A globally titled article can be assembled from accurate facts of mostly one country because that country's sources are the most plentiful. Every sentence is right and the page is still wrong. |
| Source policy: the final H2 is Sources, each original is linked there once, and prose, captions and quote attributions name the source without repeating the link. | One list lets a reviewer check every source in one place and stops a repeated link from inflating apparent authority. Attribution beside an important number stays in the text. |
| Headings use sentence case, are understandable on their own and do not all follow one syntactic mold. A vendor heading is the vendor name only. | A table of contents built on one template reads as machine-made, and descriptors stacked after a vendor name pre-judge the card. |
| Best or Top appears in the H1 and `metaTitle` only when the brief defines the comparison set, the criteria and the evidence that support the promise. | A superlative in a title is a comparative claim and needs substantiation like any other. |
| Articles of one comparison format share one skeleton and differ by vendor and evidence. `author_angle` stays empty unless the publisher supplies it. | An invented framing made texts look original at the cost of clarity. Readers find the same thing in the same place, and the format that already ranks is the reference. |
| The flow stops at a publisher checkpoint before evidence or drafting: topic row, duplicate result, resolved query, H1, angle, complete H2–H4 outline, and for a ranking the placement decision. | Evidence and writing are the expensive stages; they must be spent on a plan the publisher has seen. |
| For hybrid batches the proposal and the approval are files with hashes of `brief.md`, `sections.json` and `serp.hybrid_outline.md`, and the approval carries the API budget. | What gets written must be exactly what was approved. A brief edited after approval is detected before a paid request. |
| After approval a purely editorial heading correction does not return to the publisher; a change of meaning, positioning, hierarchy or coverage does. A change to the approved headline goes through `blog_openrouter.py amend-title`, which verifies that the body is byte-identical. | Cosmetic fixes should not cost a human round-trip, and a title change must not carry unreviewed body changes with it. |

## Evidence and entailment

| Rule | Why |
|---|---|
| `evidence.md` is the sole fact boundary for prose. No source URL, no row; two facts are not folded into one row. | The drafting model cannot look anything up. A fact recorded without a URL is stated unsourced, and a fact left out is simply absent. |
| `companies/*.mdx` is research memory. A figure that lives only in a card and has no row in this job's `evidence.md` does not go on a vendor card or into the text. | Figures leaked from cards into drafts several times and were caught by QA only because evidence was the reference. |
| Each row records the exact supporting quote and an entailment verdict (`supports`, `partial`, `no`). QA blocks any figure, price or feature that is not in evidence as a fabrication. | A quote that merely sits near the claim does not support it, and the writer has no other legitimate source. |
| Sources are tiered: government, standards and primary sources first, vendor documentation next, reputable industry sources last. Content farms and listicles are never a source of truth, and a search engine's paraphrase is not a source. | A price repeated across published articles once existed only in a search summary and belonged to a different vendor. A row is confirmed by an opened page. |
| A negative claim about a competitor needs the same proof as a positive one: a product page, a pricing page or an independent review. It is never inferred from a marketing headline or from the absence of a mention. | A card once recorded a product as missing on the strength of a slogan; the vendor sold that product. In an article it would have been a false comparative claim. |
| Before writing that a vendor "does not publish X", the legal documents are checked as well as the pricing page. A page that could not be read is our access problem, not the vendor's disclosure. | A limit described as unpublished across many articles was stated in the vendor's terms of use. "Not on the pricing page" is verifiable; "does not publish" is a claim about the whole site. |
| A vendor's positioning is described in its own published words, not as an observation of how it is "usually seen". | Such a phrase reads like a fact and cannot be verified. |
| A blocked source is retried once, marked `[fetch:403]`, capped at `partial` and paired with one corroborating live source. | The marker tells QA not to re-fetch, and a blocked page never turns into certainty. |
| When a fact is cancelled or refined, the row in `evidence.md` is marked, not deleted, and every field of the vendor card that carries it is corrected. | A cancelled claim came back with the next edit because the evidence still said so, and survived in a card field that nobody had checked. |
| Each row carries `article_link` (`required`, `optional`, `forbidden`) and `decision_use`. Competitor URLs are always `forbidden`. | Readers can verify the findings that carry the article; the page sends no traffic to pages it competes with; a citation that changes no decision is decoration. |
| Evidence writes verified facts back to `companies/` with source, note, check date and confidence. A field older than about ninety days or of low confidence is re-verified. | The next article about the same vendor starts from checked facts instead of repeating the research, and stale pricing does not pass as current. |
| Every named vendor is checked for a rebrand or discontinuation; a renamed vendor is written as the new name with the former one. | A card under an old name was once in a line-up; the reader discovers it with the first click. |
| Promotional prices are recorded separately with end date and eligibility. Regulator wording keeps actor, jurisdiction, obligation and exceptions. A case study keeps its population. | QA has caught a withdrawn promotion presented as the current price and a legal obligation attached to the wrong party. |
| QA re-fetches only the five to eight highest-risk claims and verifies the rest against the recorded quotes. | Re-opening every source doubles the evidence stage without adding independence where the risk is low. |
| Evidence rows stay in one continuous Markdown table, and internal evidence IDs never appear in public copy. | A broken table hid rows from the writer, and IDs leaked into drafts. |

## Company cards, comparisons and rankings

| Rule | Why |
|---|---|
| For every listicle, ranking, Best or Top article the publisher resolves `own_product_placement` as `ranked`, `separate` or `omit`, recorded in `job.yaml` before evidence. The default `own_product_rank: first` is not approval, and QA blocks a pending decision. | A default first place put the own product into lists of categories it does not belong to. Whether it is a genuine answer to the ranked intent is an editorial decision someone must own, and approval of a topic does not imply it. |
| Category-mismatch exception: when the list ranks a category the own product is not part of, it is never inserted into that list or table. The approved brief gives it a separate block or omits it. | Presenting a product as a member of another category is a misleading comparison, however favourable. |
| The ranked intent and the criteria are never widened to manufacture placement. List size equals the number of genuine candidates; no padding to a round number; the obvious market leaders are present. | Weak entries added to make one product look stronger by contrast, or criteria bent toward it, make the whole ranking unreliable. |
| Equal treatment: every vendor gets equally serious research and candour, with real strengths and real limitations at the same standard of evidence. Where a competitor objectively beats the own product, the article says so. Parity is not identical fields or word counts. | Comparative content is acceptable only when truthful, objective and not misleading. A softer treatment of the own product is exactly what makes a comparison misleading. |
| Ranking criteria are stated in the article and stay in the domain the own product is actually evaluated in; the comparison skeleton includes a selection-methodology section. | A reader and a compared vendor must be able to see why the order is what it is. |
| Sponsorship or material-connection labelling is a publisher decision and outside QA scope. | It depends on legal advice for the markets served, not on anything an agent can verify in the text. |
| The card form follows the content: tables for comparable facts, lists, labelled blocks or prose as the material requires. No fixed row count, paragraph count or mandatory feature block. | A fixed card template made writers drop researched material to fit it and narrate the template in the prose. |
| Between neighbouring articles vendor cards are rewritten, not copied: facts and numbers stay, wording is new. `text_overlap.py` reports shared fragments, and the threshold is a signal, not a gate. | Cards travel almost verbatim across a queue. Clarity still matters more than uniqueness, so a definition may repeat. |
| Brands listed in `config/stop-brands.json` are never mentioned anywhere: text, tables, rankings, sources, links, metadata, images. No article is written about them. The linter, the packager and the CMS exporter check the list before a review document or an API call. | A decision not to mention a brand has to hold in every field and for every agent. An editorial instruction does not reach metadata, source titles or image text; a list enforced by scripts does, and it can be narrowed again without touching the roles. |
| No outbound links to competitors; their URLs stay in the internal evidence log and in manifests with `public: false`. | The article does not send readers to the pages it competes with, while the source remains traceable for review. |
| No competitor logos or screenshots in articles. | A screenshot reproduces someone else's design and third-party rights and goes stale with the other site; logo use invites a brand-guideline dispute. The rule is written down because silence reads as permission. |
| A fact that cannot be explained without entering a topic the site never covers is not mentioned at all. | A mention without an explanation invites a question the article cannot answer. |

## Visuals

| Rule | Why |
|---|---|
| Visuals are planned after evidence and before writing (`visuals.json`). The writer knows each visual's purpose and data and inserts its `[[VISUAL:<id>]]` marker once in the planned section. | A picture added after the text either repeats it or sits unexplained. A marker lets the packager bind the image mechanically. |
| Only code-rendered charts and diagrams (bar, line, process, decision) in the site palette from `config/site-brand-tokens.json`, with the original logo inserted by the renderer. Illustrations are discussed with the publisher separately; decorative abstraction is not planned. | A code render is reproducible and its inputs can be hashed. Early chart demos drifted from the site's fonts and colours, and a model redraws a logo approximately. |
| Every plotted point and diagram node cites evidence IDs. A numeric chart carries a `data_ref` to a `D-xx` candidate that evidence has verified point by point. No intermediate points, no silently mixed units, periods or geographies; derived values carry their formula. | A chart is read as fact faster than a sentence. Categories that do not sum to a whole are not completed with an invented remainder. |
| No quota of visuals. The brief records every considered data candidate in `visual_audit` with the reason for selecting or rejecting it. `audit_visual_mix.py` flags a batch in which every article has the same set of types; the result is an editorial review, never a required chart. | A whole batch once shipped with the same two diagram types per article because no numeric originals had been looked for. A quota would have replaced that with decorative charts. |
| Planner limits: two to eight nodes, one rooted tree, at most three leaf lanes, one supported two-input layout. The renderer refuses to clip text. Title, alt and caption are at most 255 characters and are never truncated on upload. | Long labels overlapped arrows, and a CMS media field of string type rejected an upload. A silently shortened caption loses its qualifier. |
| A dashed edge must also be named in a label and in the alt or caption. | QA found control and influence drawn with the same line; a distinction carried by stroke style alone is lost on many readers. |
| Render and the geometry check run right after the plans validate, before the writer (`workflow_gate.py check --target writer`). Independent visual QA then runs alongside writing, and both branches must pass before upload and article QA. | Render and caption-length failures found after drafting stalled finished text. Running visual QA in parallel removes it from the critical path. |
| `check_visual_layout.py` re-renders, checks collisions of nodes, title, footer, arrowheads and edge labels, and produces a 390 px preview. | Arrowheads once scaled larger than the gap between nodes, and labels that read well at full size were too small at phone width. |
| `blog-visual-qa` opens every full-size PNG and its 390 px preview. A geometry PASS is not inspection. It also judges hierarchy, a legend that only repeats the single series, whether each edge label is needed and centred, and whether the axis baseline and scale represent the data honestly. | Defects that passed the automatic check: a chart crowded by its own legend and an oversized source line; labels pushed aside so they seemed attached to another connector; an auto-scaled axis that drew a minority share at full width. |
| `visual_qa.json` stores the hashes of the files viewed, and `viewed_full` and `viewed_mobile` are true only when the image was actually opened. A changed PNG, manifest, preview or renderer needs a new pass in the same QA thread. | A verdict must be bound to the exact image it was given for. |
| A visual repair that changes meaning, placement, data, alt, title, caption or quote content pauses the affected writing unit until the dependency is synchronised. Appearance-only repairs do not. | The section was written knowing what the picture shows; a changed picture makes the paragraph beside it wrong. |
| For review, checked PNGs go to the article's Google Drive review folder (`upload_review_visuals.py`), and the uploader downloads each file back and compares the hash. Upload to CMS media is a separate, explicitly authorized step, and the CMS export rejects Drive-only image IDs. | A review document needs real images, but the media library is production state. |
| After a CMS upload the uploader stores the PNG the CMS actually serves (`asset.remote_path`), and QA inspects that file beside the original render. | The CMS optimizes images and may change colours. QA has to see what the reader will see. |
| An incomplete visual is never hidden by deleting its marker; an omission is a recorded editorial decision in the manifest, and an empty plan needs an `omission_reason`. | Otherwise the gate would count a missing picture as a finished article. |
| Source labels of a visual are stored once in `sources`; the packager appends the attribution, so the caption does not repeat it. | Drafts carried a second source list inside captions. |
| When the publisher asks for a visual reassessment, the planner audits opportunities across all sections and proposes variants. The delivered image and `visuals.json` do not change until the publisher approves. | A one-visual plan needs an audit, not an assertion that one was enough, and an approved image has a hash that publication depends on. |
| No hard-coded "checked on" date appears in a visual or as the article's freshness marker; the measurement period of the data stays. | The page shows its own update date. A baked-in date becomes a stale public marker and an obligation to rewrite. |
| The cover is rendered by code from the title. For a hybrid batch `blog-visual-qa` inspects the full file and the 390 px preview, and the same checked bytes are uploaded with a hash-bound receipt. | A rendering library once stopped drawing in the middle of a title without an error. The file that was inspected must be the file that is published. |

## Expert quotes and their approval

| Rule | Why |
|---|---|
| A separate role prepares exact comment proposals before writing (`expert_quotes.json`). The writer inserts the exact text and attribution and never composes an attributed statement. | Words under a real person's name cannot be a by-product of drafting. |
| There is no minimum or maximum number of comments. Each must explain a decision, qualify a trade-off or give a practical recommendation that the surrounding prose does not. | A fixed count produced comments that repeated the text. |
| Verified outside candidates are evaluated before staff comments, and there is no automatic fallback to a staff comment. | The first quote contract accepted only staff speakers, so external voices found in research could not reach the article. |
| An external quote is verbatim, at most 25 words, with a stable HTTPS original, publication date and exact location, and keeps the author's qualification. | It can be checked against the original by anyone, and a short excerpt stays within fair quotation. |
| Staff attribution equals the exact `name` field of the author or editor in the CMS, read by `fetch_blog_profiles.py` from real article relations. The snapshot `raw/speaker-profiles.json` is part of the QA receipt. | A transliteration or a spelling from another byline was once used; the name shown under a comment must match the author profile on the site. |
| Facts, prices, figures and legal statements inside a comment reference evidence IDs. An opinion is never evidence, and no interview, experience, client case or test is invented. | A quote must not launder a claim that failed verification. |
| Statuses are `proposed`, `approved`, `rejected`. No agent may set `approved`. Proposed comments reach the review document with a note outside the article; the CMS export requires approval of the exact text and attribution. | Only the named person, or the publisher for an external quotation, can agree to the words. A machine PASS is a factual check, not consent. |
| `workflow_gate.py approve-quotes` and `approve-review` record who approved and where the decision is; the scripts do not verify identity. Any revision returns a quote to `proposed` and removes the old approval. | An approval is valid for the exact wording it was given for. |
| A rejected quote is removed from the article and never silently replaced by the writer. | A replacement would be a new unapproved statement. |
| When a quotation's required attribution link would point to a competitor, the quote is replaced with a verified independent original before QA. | The rule on clickable attribution and the ban on competitor links cannot both hold for such a quote. |

## The writer

| Rule | Why |
|---|---|
| One writer per article in one persistent conversation. A writing unit is one complete H2 with every approved H3 and H4 beneath it. | A whole article in one request comes out thin. Splitting further, one subsection per turn, produced dozens of turns per article, and more time passed between turns than inside them. |
| The dispatch plan is loaded once (`writer_dispatch.py`), and the next unit is sent as soon as the previous one completes. `--next` and `running_state.md` are for recovery only. | Polling files and reloading state on every turn was most of the waiting time. The conversation already remembers what was written. |
| Between units the parent supplies no checklist, word budget or feedback. The standing instruction is to write the unit fully and naturally, deeper than the competing pages where evidence allows, without padding or retelling earlier sections. | Feedback between units turns the writer into a second editor and the parent into a content author. |
| When evidence is missing the writer writes around the gap and reports it. | A gap filled from memory or from a vendor card becomes an unverified statement that reads well. |
| The writer reads `knowledge/writer-style.md`, the compact write-first form of the anti-AI rules. The full humanizer catalogue is the editor's diagnostic tool. | Avoiding a pattern while drafting is cheaper than removing it afterwards, and a long catalogue at drafting time crowds out the content. |
| The writer's "never" list covers search talk, instruction echo, verification narration, roadmap items and dates, absence claims, and internal links outside `config/site-urls.json` or in another language. | Each item was struck out by the publisher at least once. An English article once linked to a page in another language because the address did not show it. |
| The house manner is measured against published articles that rank: address the reader, name the brand where the mention carries a fact, use lists for real enumerations, keep "X, not Y" contrasts for real confusions. | A comparison with the first machine drafts showed several times fewer list items, direct addresses and brand mentions in the drafts, and far more ornamental contrasts. |
| After the last unit, `writer_dispatch.py --check` and `assemble_sections.py` verify and assemble the draft. A missing or truncated section returns to the same writer as a technical defect. | The parent never hand-writes the missing part. |

## Hybrid writer and first critic through OpenRouter

| Rule | Why |
|---|---|
| New-topic jobs set `production_text_backend: openrouter_hybrid`: a fast inexpensive model drafts through OpenRouter, a second one gives a first-pass review of the assembled draft, and research, evidence, editing and independent QA stay native. | Drafting from a verified packet under exact headings is the stage where a cheaper model holds quality. In trials every raw draft still needed the native editor and QA, so the judgement stages were not moved. |
| One complete H2 per request, in one conversation per article that carries the earlier verified outputs. | A model asked for the whole article, or left free to continue, wrote several sections in one response and was cut off mid-text. |
| The first-pass critic is kept, and its findings are advisory: the native editor checks each one against the evidence. | In a controlled comparison, drafts that skipped the critic kept more blockers in complex comparisons. A critic finding was also once false, and following it removed a required source. |
| The route is pinned in `config/blog-openrouter.json` — model, exact version, provider — and verified before and in every response. There is no fallback to another model, provider or backend, and no automatic retry. | The same model behaved differently by provider: one truncated responses, another route was refused by account settings. A silent fallback changes quality and price without anyone deciding it. |
| Reasoning settings and the output ceiling are part of the pinned route. | A model once spent its output on reasoning and returned no text, and the attempt was still charged. A long review was cut off at a smaller ceiling. |
| `prepare` freezes the packet and sends no paid request. `execute` refuses to run when a live job input or policy card has changed since; a new revision is prepared instead. | Paid text must be generated from exactly the inputs that were approved and checked. |
| The batch budget is approved by the publisher together with the briefs and bound to the approval file by hash. Each call is checked against the price cap and the remaining budget, and charged failures count. | Budget approved separately from the plan, or checked after the fact, is how API spend drifts. |
| Every attempt writes an intent before the request and a receipt after it. An unknown charge or an incomplete intent blocks new calls until it is reconciled. `--retry-failed` is only for known, reconciled failures. | After a transport error it is not known whether the provider charged. A blind retry pays twice, and a skipped reconciliation hides a charge. |
| Import accepts only a complete response from the pinned route whose headings match the approved strings, levels and order, and which contains each planned visual marker and quote block exactly once. | Models changed approved headings, added neighbouring sections or returned a full article for one unit. |
| A heading that differs only in punctuation or wording is restored through an audited restoration record bound to the raw output hash. A missing section or broken hierarchy needs a corrected model output. | Mechanical restoration is safe only when nothing but the heading text differs, and the audit keeps the import honest about what was changed. |
| After a QA block, substantive defects are listed by approved H2 ID in `raw/openrouter-rework-plan.json`, and the same writer model patches only those spans in the current edited text; unaffected paragraphs stay verbatim. | A full regeneration discards the editor's work and reopens every passed gate. |
| Actual spend is read from receipts with `blog_openrouter.py cost`, per article and in total, including charged retries. Unreconciled attempts are reported separately from known spend. | An estimate from token counts is not what was charged. |

## Editing and humanization

| Rule | Why |
|---|---|
| The edit is diagnostic-first and coverage-preserving: defects are mapped to positioning, evidence, structure, repetition, voice or a named AI pattern, and only failing passages are patched. Good prose stays as it is. | An editor who rewrites in a shorter style of their own loses approved coverage while every sentence looks better. |
| The editor never removes a planned section, vendor card, required table, comparison axis or evidence-backed argument to tighten the draft. Compression is a side effect of fixing defects, never an objective, and there is no length ceiling. | Completeness is judged against the approved hierarchy, not against article length. |
| A substantive gap is recorded as `writer-rework: <section> — <gap>` and goes back to the writer; a section that needs new facts goes through evidence first. | An editor who fills a gap invents substance, and one who cuts around it hides the gap from QA. |
| Every cut evidence-backed fact is listed in `editor_issues.md` under "Cut facts" with the reason. | QA cannot see what was lost unless it is written down. |
| The humanizer is one process over the whole assembled article — analysis, targeted edit, meaning check — including headings, cards, lists, captions and the ending. | Patterns such as repeated card openings or one heading template are visible only across the whole page. |
| The pattern catalogue has no mechanical bans on words, dashes, triples or legal qualifiers. Real distinctions, complete checklists, useful parallel structure and qualifications are preserved. | A list of banned devices applied mechanically removed "may" and "usually" to sound firmer and replaced plain facts with invented specifics. |
| The AI-Score is an editorial signal. It is not an authorship detector, not a target and not a QA verdict. | A low score was once offered as proof that a text was fine while readers still found it unnatural. |
| After editing, the editor compares `edited.md` with the draft: every independent fact, qualifier, actor, link, quote, visual block and planned point is retained, and a possibility is not turned into a guarantee. | Style edits are where certainty silently increases. |
| The blog has no separate humanization agent or pass. | The editor already receives the complete assembled article, and a second rewriting stage would be a second chance to lose meaning. |
| Research-process artifacts and verification narration are rewritten into the reader-relevant fact: no HTTP status codes, no "the page confirms", no "the domain redirects". | The reader needs to know that pricing is not published, not that a request returned an error. |
| Rework runs in patch mode in the same editor thread: only the named sections are re-edited, the rest stays byte-identical, and the editor returns the changed section names. | It keeps the QA delta small enough for a targeted re-check. |
| `article_delta.py editor-report` gives QA per-section word deltas and heading changes as a signal of lost coverage, not as a percentage gate. | A large cut may be justified de-duplication, and a small one may remove the key fact. |
| "X, not Y" contrasts are counted in two ways: QA counts strict appositions, the linter counts a broader set. An assignment names which count it means. | Agents twice took the ceiling of one count for the other and cut contrasts that helped the reader. |

## The mechanical linter and independent QA

| Rule | Why |
|---|---|
| `scripts/lint_article.py` checks only what is visible in a line: stop-listed brands, banned topics, labels and claims next to the brand, abbreviation case, link targets and their language, table width, quotation typography, leftover markers. Matters of meaning stay with QA. | Every rule is the trace of a publisher edit that used to be caught by eye. A script does not get tired and costs nothing; an agent that reads and reasons should not be spent on it. |
| Company policy for the linter is data in `config/brand-rules.json`; writing-craft rules and the mechanics stay in the script. | A team adapting the flow changes its product rules without editing code, and the tests pin both. |
| A forbidden claim is blocked only in a clause attributed to the brand: the linter splits clauses, follows pronouns and self-reference nouns, treats table cells as separate and does not count a negation as the claim. | A sentence about another vendor next to the brand name, and a plain market explanation, were flagged as self-description. |
| Forbidden vocabulary about the own product may still describe the market and other vendors. | Product restrictions were once applied to an educational section and blocked the ordinary subject of the article. |
| Deterministic checks — section check, word count, lint, research links, overlap — run before the first model QA pass, and mechanical failures go to the responsible specialist. | A QA pass spent on a missing link is a wasted QA pass. |
| `scripts/check_article.py` bundles assembly, lint, overlap, HTML and sanitizer checks into one command with a short report; it is mutating. | Run one by one, these checks sent the full article text through the orchestrator's shell many times per article. |
| `blog-qa-factcheck` is the final gate. It writes `qa_report.md` with each gate PASS or BLOCK and never edits prose. Length is not a gate. | A reviewer who edits cannot give an independent verdict on the result. |
| QA judges what a script cannot: whether the information-gain items are actually delivered, whether each claim is entailed by its row, whether the dominant intent is answered first, whether ranking rules were followed. Script counts are not replaced by a model's impression. | An early QA accepted the presence of a topic where the reader's question stayed unanswered; a model also misjudges exact phrase counts by reading. |
| QA inspects the materialized article: actual uploaded images beside their renders, captions, tables, exact quote text and attribution. It never claims inspection from JSON alone. | A body paragraph that keeps a qualifier does not repair an overbroad caption standing alone. |
| After QA passes, the parent reads a compact packet from `build_orchestrator_review.py`: metadata, own-product excerpts, risk-language hits, links, QA verdict. A rule defect found there is fixed in the rule source as well as in the text. | Fixing only the text guarantees the same defect in the next article. |

## QA receipts and rework routing

| Rule | Why |
|---|---|
| `workflow_gate.py seal-qa` binds content, visual and quote specs, evidence, metadata and the QA report in `qa_receipt.json`. Any later edit requires repackaging, the affected QA and a new receipt. | Without it a later text change rides on an old PASS. Conflicting verdict lines in one report grant nothing. |
| The normal budget is one full edit, one full QA and at most one targeted correction with a re-check. A second correction is allowed only for a narrowly bounded factual, legal, positioning or publication-safety defect. | Open-ended polish loops cost more than the article and rarely change the verdict. |
| On BLOCK a substantive gap goes to the same writer, an editorial defect to the same editor, and the re-check to the same QA thread with a generated diff (`article_delta.py snapshot` and `report`). | The original thread already holds the context, and a second full pass costs as much as the first. |
| A re-check covers only the failed gates plus entailment and style of the changed sections, and adds no new advisory requests. A full rerun happens only when the diff changes structure or unrelated sections. | The purpose is to close named blockers in one cycle, not to start a new editorial round. |
| A QA PASS is not human approval. Proposed comments may pass QA and still cannot reach the CMS. | Factual correctness and a person's consent to words under their name are different facts. |

## Review documents

| Rule | Why |
|---|---|
| Immediately after QA passes and the package builds, `gdoc_review.py push` creates the review document, stores its URL in the job and moves the topic-sheet row to `in review`. A failed push or sync is a workflow failure. | Review is part of the route. An article reported ready without its review link is not ready for anyone. |
| The push checks the current QA receipt and all actual images before creating any folder or document, inserts native images with visible captions, verifies their object IDs and stores a round receipt. | The document must show what QA saw. Markdown image syntax or a marker in a document is not an image. |
| A note about proposed comments stands outside the article body; `pull` excludes it from the diff and reports deleted or replaced images as well as text edits. | The reviewer must see which words are not yet approved, and that note must not come back as an article edit. |
| Later rounds are pushed with the previous round as baseline so that changes arrive highlighted. | The reviewer re-reads what changed, not the whole article. |
| The Docs API cannot set alt or title on an inline image. The document carries the image and a visible caption; the metadata stays in the receipt. | Claiming otherwise would hide that alt text is verified only on the site side. |

## CMS export gates and publication

| Rule | Why |
|---|---|
| The CMS gate checks the approved article and quote wording, a current QA receipt, the absence of markers and placeholders, real images, metadata limits, the stop-list and the duplicate decision. No agent may waive an export failure. | The export is the last point where a stale or unapproved version can be stopped by a machine. |
| `strapi_publish.py` writes a draft first, reads the stored HTML back and honours `--publish` only when it matches. A mismatch leaves a tracked draft; the retry uses `--update` with the recorded ID. | A CMS can alter markup on save, and a blind retry creates a duplicate record. |
| Packaging proves that the HTML survives the production-equivalent sanitizer (`tools/sanitize/check.js`). Body headings start at H2 and stop at H4; the single H1 in `edited.md` is expected and the converter moves it to the title field. | Anything outside the allow-list disappears silently on the site. Two agents once disagreed about the H1: one removed it from the working file, another flagged it as a defect. |
| The CMS is not modified for the flow. The image title is kept in the manifest and as the media name and omitted from the exported HTML. | The current CMS strips that attribute; the flow adapts to the contract instead of requiring a deploy. |
| Publication order is draft, cover, publish. For a checked draft `--cover-receipt` binds the publish step to the uploaded cover, and content, H1, `metaTitle` and cover are verified on the exact draft before its status changes. | An article should not go live without a cover, and the record published must be the record that was checked. |
| After a transport error the exact record and receipt are read back before any repeated mutation. An ambiguous create request is never replayed blindly. | A timeout does not mean the write failed. |
| After publication the public URL, canonical, H1, cover and body images are verified, and only then does `temnik.py publish` update the row. | The stored record and the public page are separate facts. |
| Published URLs are submitted to IndexNow in one request per batch, with the site's own key, and the HTTP receipt is saved. A 200 or 202 means the URLs were received. | The receipt proves what was sent; indexing is a separate fact, and a key belongs to one site. |

## Refresh of published pages

| Rule | Why |
|---|---|
| Before a page is selected for a refresh, a fresh Google URL Inspection of its exact URL is run and its dated receipt read. A page that is not indexed is recorded in the topic sheet and skipped. | Several pages once went through a full query-driven refresh although they were not in the index, which is why they had no queries. The check costs one request; the refresh costs a full cycle. |
| An unavailable check is recorded as unknown and skipped, never as "not indexed". Index membership is not inferred from zero queries, HTTP 200, sitemap presence or an IndexNow receipt, and a crawl record from another search engine is shown as unconfirmed. | An API failure and an exclusion are different facts, and each of the proxies has been wrong. |
| A refresh is a separate versioned job with `article_refresh_version: 1`. The original job and the published record are read-only; each cycle has its own evidence, QA receipt and review document. | An old QA verdict does not approve a new version, and the original production history must stay readable. |
| Query phrases, lemmas and n-grams are discovery aids. Every returned query gets exactly one reasoned decision: `covered`, `expand`, `link`, `separate_topic` or `irrelevant`. A missing phrase is a measured signal, not an instruction to insert it. | Inserting every missing phrase produces keyword stuffing, and ignoring the list produces a refresh unrelated to demand. |
| Coverage is counted by script before and after editing: exact phrase and ordered lemma sequence. Synonyms, reordering and gaps never count. QA does not substitute its impression for the counts. | A model judges phrase presence by reading and gets it wrong. The local NLP models are pinned so the same text always gives the same count. |
| The query window is page-only, at most ninety days and never earlier than publication. Missing or anonymized rows are unknown, not zero. | Queries of other pages matched by a slug keyword are not this page's demand, and a zero invented from missing data distorts every comparison. |
| Agents read a compact `briefing.json` with every query and term but without the repeated location arrays; the full report stays authoritative for gates and seals. | The full location dump is megabytes per role. |
| The loss of a full query or a protected term that was present before needs a recorded reason; other frequency changes stay visible advisories. | A refresh must not quietly remove the wording a page already ranks for. |
| The writer starts each retained H2 from the literal baseline text and patches only justified spans, recording the reader-value addition, fact correction or link behind each change. Retained units are copied mechanically. | The first refresh pilot rewrote most blocks of a published article that already worked. Returning a whole H2 is an output format, not permission to rephrase it. |
| The review document highlights changed words against the published baseline (`--highlight-mode words`), and the actual diff is inspected for needless rephrasing first. | Block-level highlighting made a broad rewrite look like a page of legitimate changes. |
| The primary intent, the H1 and the URL are protected. No visual or quote is mandatory in a refresh; an empty plan carries a reason tied to this update. | The page already ranks; the refresh must improve it without changing what it is. |
| Publication updates the existing CMS record in place, preserving first publication date, author, editors, cover, tags, indexability and URL, with a snapshot before the write and a restore request on mismatch. A refresh job cannot create a record. | An unpublish-and-republish cycle or a new record would lose the page's history and signals. |
| The next review is planned 15–30 days after the actual published update. Review readiness is not publication and starts no effect window. | The effect of an update can only be measured from the day readers got it. |

## Translation

| Rule | Why |
|---|---|
| A translation is a separate job with `article_translation_version: 1`. No topic selection, SERP, research or ranking decision is run. | It is neither a new topic nor a refresh, and running their stages would silently re-author the article. |
| The current published record is captured as an immutable snapshot with hashes. Unsupported HTML forms block the snapshot before it is written, and a live-source drift check runs before package and review. | Fidelity can be judged only against a fixed source, and a conversion that loses a table cell must fail early. |
| The drift check compares article fields and the ordered author and editor IDs, not profile attributes. | An edited author biography once blocked every export although no article had changed. |
| Three roles: a light-model translator, a strong-model editor and a strong-model independent QA. | A translation draft is checked twice afterwards, so the cheap model is safe there and nowhere later. |
| Fidelity protects facts, actors, numbers, negations, qualifiers and coverage of headings, lists and tables. It does not protect the source language's syntax, sentence boundaries or formulaic wording. | A first pilot kept calques and repeated frames, and the editor justified them as parity with the source. |
| QA first reads the translation on its own as a native text, then compares it with the source. New jobs carry separate `natural_ru_status` and `style_status`; both must pass, and a fidelity PASS alone never establishes review readiness. | A text can preserve every fact and still be unnatural. A low AI-Score or the editor's reassurance is not evidence. |
| Whole-article feedback about unnatural language requires a whole-article diagnosis with concrete before and after excerpts in the editor's report. | A few replaced calques did not answer a complaint about the whole text. |
| Historical claims of the source are never silently corrected, updated or strengthened; conflicts with current rules are logged as source-policy findings. `fresh_fact_verification` is false and `publication_status` is `NOT_ASSESSED`. | A translation is not a fact check, and the review document must not suggest that it was one. |
| A departure from the source's meaning is allowed only on an actual publisher instruction for this job, recorded with the exact quote and its path, and verified independently by QA. A repository example or another article's feedback is never authorization. | An editor of a different article once cited another job's example as approval to weaken a recommendation. |
| The translator may work unit by unit (`translation_units_version: 1`): title and preamble, then each complete source H2, in the same thread; assembly runs only after every unit receipt passes and never overwrites a differing draft. | Long articles came back incomplete when translated in one response. |
| Internal links point only to verified pages in the target language; otherwise the words stay without a link and the reason is recorded. | Invented locale URLs are broken links at best. |
| A deterministic check scans the final text and visible metadata for leaked tool markup and sandbox references before package, seal and review. | Such markers are invisible in a style review and obvious to a reader. |
| The normal CMS export refuses translation jobs. A dedicated script creates a linked draft after a hash-bound authorization, and a separate one publishes it; each writes the attempt before the request and never repeats an ambiguous create. | The localization link, the empty cover and the untouched source record need their own checks, and a duplicate localization is hard to undo. |
| A publication request gets a scoped readiness QA against current product and legal rules; a blocker becomes a minimal before-and-after proposal for the publisher. | Permission to publish cannot make an outdated claim in the source true. |

## Metrics and usage accounting

| Rule | Why |
|---|---|
| Every metrics mutation holds a per-job lock across read, modify and atomic replace. | Two stages registered at the same moment once overwrote each other, and a stage disappeared from the log. |
| `start` freezes the list of expected stages from the job's flags; a missing planned stage makes the report `INCOMPLETE`. | A report that silently lacks a stage looks cheaper and faster than the run was. |
| A run uses `--scope full`, or `--scope preflight` up to the brief checkpoint and a `production` phase after approval. Each later user turn is its own phase. | Time spent waiting for a human answer is not model work and must not enter the article total. |
| Each stage is closed as soon as its agent or script finishes, and a specialist binds its own thread ID to the stage before work. | Stages closed in bulk overlapped and inflated the totals; a writer stage closed after its first part undercounted the writer. |
| The report separates completed-turn execution from dispatch, between-turn and closing delays. Missing events are unknown, not zero. | It showed that handoffs, not generation, were the largest part of the writer's wall time. |
| The provider rollout is the authority for the model and effort actually used; a mismatch with the routing file, or ambiguous attribution, gives `INCOMPLETE` instead of an estimate. | A specialist once started on the wrong model for a moment; an estimate would have hidden it. |
| The weekly subscription percentage is a coarse account-wide observation. It is never derived from token counts or attributed to one agent when stages overlap. | Token counters measure processed context, most of it cached, not quota. |
| The production subtotal and the whole-lifecycle total are reported separately; review, feedback rework and publication are later phases. | Otherwise two articles with different review histories cannot be compared. |
| API spend of hybrid jobs comes from receipts, not from the metrics report. | Subscription usage and per-call charges are different currencies. |

## Model routing

| Rule | Why |
|---|---|
| `config/codex-model-routing.json` names a model and reasoning effort for every role, and the parent passes them at spawn. The agent profiles in `.codex/agents/` carry no model pins. | One file to change, and a specialist never inherits the orchestrator's model by accident. |
| Research, brief, evidence, editing and QA run on the strong model; vendor cards, visual planning, comments and the native writer on a mid model; the translator on a light one. | Judgement about sources and what the reader needs propagates to everything after it. Work from a verified packet under a tight contract does not need the same model. |
| Reasoning effort is `medium` for every specialist. | Higher effort raised cost and time without a measured gain on work that is bounded by files and validators. |
| The metrics report fails closed when the runtime model or effort differs from the routing file, and `validate_codex_setup.py` checks roles, profiles and routes after any change to them. | A route that exists only in a document drifts from what actually runs. |
| OpenRouter routes live in their own file with provider and price caps, separate from the native routing. | They are paid per call and need guarantees the subscription routes do not. |
